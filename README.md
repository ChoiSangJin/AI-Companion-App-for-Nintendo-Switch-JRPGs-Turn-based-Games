# Switch 공략 컴패니언

Nintendo Switch 1·2 JRPG/턴제 게임용 개인 Android 앱입니다. Flutter Material 3 다크 UI이며 서버·로그인 없이 동작합니다. **필요한 공략 찾기 → 실행할 항목 고정 → 내 목표 현황판에서 진행 관리**를 중심으로 사용합니다.

- 포켓몬: 시리즈 검색으로 작품을 선택하고 스토리 추천 파티·입수 시점·대체 멤버·진행 동선을 확인합니다.
- 파이어 엠블렘 및 직업 시스템 게임: 캐릭터 목록에서 선택하면 추천 직업과 초기→중간→최종 육성 단계 및 전직 조건을 봅니다. 이름 직접 입력도 가능합니다.
- 페르소나 및 다른 JRPG: 월·챕터를 한 번 선택하고 해당 구간의 놓치기 쉬운 요소·마감·선행 조건을 체크리스트로 확인합니다. 난이도·루트·DLC 등 추천 조건도 선택적으로 저장합니다.
- 구조화된 공략은 출처와 확인 시점을 함께 자동 저장합니다. 같은 작품·에디션·대상·구간·조건·모델의 결과는 오프라인에서 재사용하며, 새로고침할 때만 다시 요청합니다. 남아 있는 동일한 할 일의 완료 상태는 유지합니다.
- `내 공략집`에서 저장한 공략을 검색·수정·삭제하고 완료 항목을 숨길 수 있습니다. 과거 기록은 당시 구간·조건으로 다시 열립니다.
- 추가 질문 검색과 붙여넣은 공략의 체크리스트 변환도 유지합니다. API 키는 Android 보안 저장소, 게임·공략·체크 상태는 로컬 JSON에 저장합니다.
- 기존 v1.0.x의 게임·공략·선택·체크 상태를 그대로 읽습니다. 내 게임 목록은 자동으로 채우지 않고 직접 선택한 작품만 등록합니다.

## 내 목표 현황판

공략 결과와 내 공략집의 항목별 핀 버튼으로 캐릭터 육성 계획·포켓몬 확보 목표·구간별 할 일을 고정합니다. 메인에는 현재 게임의 진행 중인 목표를 먼저 표시합니다. 좁은 화면은 한 열, 여유가 있는 화면은 두 열 카드로 표시하며 상단 공략 찾기 버튼으로 다른 공략에 바로 접근할 수 있습니다.

- 육성 목표: 다음 미완료 단계와 조건을 확인하고 `이 단계 완료`로 진행합니다. 상세 화면의 체크박스로 이전 단계도 되돌릴 수 있습니다.
- 포획·퀘스트 등 할 일: 입수 조건과 마감을 확인하고 완료 처리합니다. 완료한 목표는 접힌 영역에 모으며 다시 열어 완료를 취소할 수 있습니다.
- 직접 추가: AI 키·인터넷 없이 게임별 목표 이름, 할 일, 메모를 작성합니다. 상세 화면에서 이름·메모 및 직접 작성한 할 일을 수정할 수 있습니다.
- 고정한 목표에는 당시 공략·출처·진행 구간·추천 조건의 사본과 별도의 진행 기록을 보관합니다. 원본 공략 수정·새로고침·삭제가 고정된 계획이나 완료 상태를 덮어쓰지 않습니다. 새 추천을 사용하려면 새 항목을 고정하고 이전 목표를 해제하세요.
- 같은 공략 항목을 반복해서 고정해도 목표가 중복되거나 진행 기록이 초기화되지 않습니다. 저장 실패 시 기존 목표를 복원하며 재시도할 수 있습니다.
- 목표 고정 해제는 해당 목표의 진행 기록·메모만 삭제합니다. 게임 삭제는 확인 후 그 게임의 공략과 목표를 함께 삭제합니다.

기존 v1.0.x·v1.1.x 데이터는 목표가 없는 상태로 호환됩니다. API 키는 그대로 보안 저장소에 유지되며 모든 목표와 진행 기록은 기기에만 저장합니다.

## 게임 목록과 공략 유형

`lib/data/game_catalog.dart`에 Switch 계열 **22개 작품·에디션의 초기 목록**과 공식 참고 링크, 게임 시스템별 공략 메뉴를 수록했습니다. 전체 출시 라이브러리 또는 검수된 공략 사실 DB는 아닙니다. 목록에 없는 게임은 직접 추가할 수 있습니다. 정확한 에디션을 선택해야 버전 차이가 프롬프트에 반영됩니다.

새 작품은 `GameDefinition` 데이터로 추가합니다. 전술·직업형은 캐릭터와 육성 경로, 포켓몬은 파티와 동선, 캘린더형은 월 단위 놓칠 요소를 공통 화면으로 표시합니다. 작품마다 화면·조건문을 복제하지 않습니다. 만자천홍처럼 발매·공략 공개 여부를 별도 확인해야 하는 항목은 표시하고, 요청 시 실제 공개 정보부터 검색하도록 합니다.

공략은 Gemini Google Search grounding을 사용합니다. 자체적으로 새 육성법을 만드는 대신, 작품·버전·난이도·입수 시점에 맞는 공개 커뮤니티·위키 공략을 찾아 조건과 대체 경로를 요약하도록 요청합니다. 검색으로 확인한 자료를 사용하며 한 사이트의 의견을 보편적인 정답으로 단정하지 않도록 합니다. 정확한 작품·플랫폼의 발매 및 공략 공개 여부, 캐릭터·전직·입수 조건을 검색하도록 요청합니다. 출처가 없거나 응답 유형·진행 범위가 다르거나 필수 추천 조건이 부족하면 저장하지 않습니다. 확인할 수 없다는 응답은 오류로 표시하며 다른 작품의 정보를 대체 데이터로 사용하지 않습니다. 이는 응답 형식·범위 검사이며 웹 출처의 사실성이나 AI의 스포일러 차단을 완전히 보장하지 않습니다.

API 키와 모델은 설정의 **AI 연결 안내**에서 연결합니다. 새 사용자는 모델 이름을 직접 입력할 필요가 없습니다. 실제 Gemini 호출에는 개인 키와 사용량이 필요합니다.

## 처음 사용하는 사람을 위한 AI 연결

1. **AI Studio에서 API 키 만들기** 버튼으로 [Google 공식 발급 페이지](https://aistudio.google.com/apikey)를 엽니다. Google 계정 로그인·약관 확인 후 API 키 만들기를 선택하고, 프로젝트 선택이 나오면 공식 화면 안내에 따라 선택·생성합니다.
2. 키 값을 복사해 앱의 **복사한 키 붙여넣기**로 입력합니다. 키는 가려서 표시하며 사용자가 누를 때만 클립보드를 읽습니다. 발급 화면이 다르면 공식 발급 안내, 계정·지역 이용 조건과 요금 링크를 사용할 수 있습니다.
3. **키 확인하고 공식 모델 불러오기**로 Google `GET /v1beta/models`의 현재 목록을 최신 버전순으로 확인합니다. 이 목록은 무료 모델 목록이 아닙니다. 처음에는 안정 Flash를 연결 후보로 선택하며, 기존 키의 저장 모델은 유지합니다. 미리보기·실험용·자동 변경 별칭은 별도로 표시합니다.
4. **이 설정으로 저장**을 누르면 선택한 모델로 공개 질문 1회의 검색 연결을 확인한 뒤 저장합니다. 실패하면 키·모델을 저장하지 않습니다. 다른 Flash를 직접 선택해 확인할 수 있으며 자동 재시도·자동 모델 전환은 하지 않습니다. 같은 키·모델로 이미 테스트에 성공했다면 저장 시 중복 호출하지 않습니다. 키 변경 시 검증을 폐기합니다. 키 삭제는 별도 확인을 거치며 목표·공략은 유지합니다.

모델 목록 API에는 요금제·남은 할당량·출시일·검색 지원 정보가 없습니다. 검색 연결 성공도 현재 요청 성공을 뜻하며 무료 요금이나 이후 사용을 보장하지 않습니다. 테스트는 API 사용량을 소모하며 결제가 연결된 프로젝트에서는 요금이 발생할 수 있습니다. Gemini 앱 구독과 API 요금은 별도입니다. 앱에서 결제를 등록하거나 자동으로 유료 모델로 전환하지 않습니다.

429 오류는 Google의 구조화된 QuotaFailure 정보가 있는 경우 무료 할당량 0, 일일 한도, 분당 제한을 구분합니다. 정보가 없으면 원인을 추정하지 않고 AI Studio 사용량·한도 확인과 다른 Flash 테스트를 안내합니다. 원문 오류 메시지·키는 표시하지 않습니다. 무료 한도가 0이면 처음 사용해도 실패할 수 있으며, 같은 프로젝트에 새 키를 만들어도 프로젝트 한도가 늘지 않습니다.

모델 목록·지원 정보는 앱에 고정하지 않고 공식 API에서 매번 조회합니다. 참고한 공식 프로토콜은 [Google Model 정의](https://github.com/googleapis/googleapis/blob/master/google/ai/generativelanguage/v1beta/model.proto), [ListModels 정의](https://github.com/googleapis/googleapis/blob/master/google/ai/generativelanguage/v1beta/model_service.proto) 및 [공식 모델 안내](https://ai.google.dev/gemini-api/docs/models)입니다. API 키를 채팅·로그·저장소에 올리지 마세요.

## 개발

최신 Flutter stable, Java 17, Android SDK가 필요합니다. Android 최소 버전과 타겟은 Flutter stable 기본값을 따릅니다. `android`는 Flutter의 stable Android Kotlin 템플릿 기준입니다 (AGP 9.1.0 / Gradle 9.3.1).

```sh
flutter pub get
# pubspec.lock에 해석된 의존성 버전이 포함되어 있습니다.
dart format lib test
flutter analyze
flutter test
flutter run
```

`lib/models`는 데이터 모델, `lib/services/gemini.dart`는 REST 요청·파서, `lib/services/storage.dart`는 로컬 저장소, `lib/main.dart`와 `lib/widgets`는 UI, `guide_repository.dart`는 자동 저장·재사용을 담당합니다. 테스트에는 영속성, 손상된 데이터 보호, 요청 컨텍스트, JSON 파서, API 오류, 출처 없는 응답 거부와 게임 추가 UI가 포함됩니다.

AI 호출을 제외한 공략집은 네트워크가 필요하지 않습니다. Gemini 키는 앱에서만 입력하며 저장소·CI에 넣지 않습니다. 실제 Gemini API 검증에는 사용자의 유효한 키와 사용량이 필요합니다. 모델 가용성·쿼터·Google 검색 지원은 계정과 모델에 따라 다릅니다.

## Android APK 배포

앱 아이콘 원본은 `assets/branding/launcher_icon.png`입니다. Android의 밀도별 아이콘과 적응형 아이콘은 다음 명령으로 다시 생성할 수 있습니다.

```sh
dart run flutter_launcher_icons
```

`flutter_launcher_icons.yaml`의 배경색과 안전 영역을 유지하세요. 앱 아이콘은 직접 생성한 공략집·체크리스트 디자인이며 Nintendo 공식 로고를 사용하지 않습니다.

`.github/workflows/ci.yml`은 PR과 main/기능 브랜치에서 분석·테스트·ARM64 디버그 빌드를 실행합니다. `.github/workflows/release.yml`은 `v*` 태그 또는 수동 실행으로 **릴리즈 키로 서명한 ARM64 APK**와 SHA-256 체크섬을 GitHub Releases에 게시합니다. Play Store 배포는 포함하지 않습니다.

동일한 키를 계속 보관해야 기존 앱을 업데이트할 수 있습니다. 다음 GitHub Actions repository secrets가 필요합니다. 비밀 값은 채팅이나 저장소에 올리지 마세요.

| Secret | 용도 |
| --- | --- |
| `ANDROID_KEYSTORE_BASE64` | 릴리즈 JKS 파일의 Base64 |
| `ANDROID_STORE_PASSWORD` | JKS 암호 |
| `ANDROID_KEY_ALIAS` | 서명 키 alias |
| `ANDROID_KEY_PASSWORD` | 서명 키 암호 |

기존 키가 없다면 안전한 로컬 디렉터리에서 생성하고 백업합니다 (대화형 암호 입력).

```sh
keytool -genkeypair -keystore release.jks -alias switch-companion \
  -keyalg RSA -keysize 3072 -validity 10000 \
  -dname "CN=Switch Companion"
# GitHub Settings > Secrets and variables > Actions에 위 네 가지를 등록합니다.
# macOS: base64 -i release.jks | pbcopy
# Linux: base64 -w 0 release.jks (출력을 공개 로그에 남기지 마세요)
```

`pubspec.yaml`의 버전과 태그를 일치시켜 배포합니다. 현재 버전은 `v1.3.2`입니다. 수동 실행 시에도 main에 포함된 커밋을 대상으로 선택하세요.

```sh
git tag v1.3.2
git push origin v1.3.2
```

빌드 명령은 `flutter build apk --release --target-platform android-arm64 --split-per-abi`이며 산출물은 `build/app/outputs/flutter-apk/app-arm64-v8a-release.apk`입니다. 로컬 릴리즈 빌드에는 `ANDROID_KEYSTORE_PATH` (절대 경로), `ANDROID_STORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`가 필요합니다. 서명 설정 없이 릴리즈 배포를 진행하지 않습니다.

## 데이터와 제한

게임·규칙·검색어·붙여넣은 공략은 요청 시 Google Gemini에 전송되며 사용료가 발생할 수 있습니다. 로컬 API 키는 보안 저장소에 있지만 기기를 완전히 신뢰할 수 없는 환경에서는 노출될 수 있습니다. AI 답변의 정확성이나 스포일러 차단은 보장되지 않습니다. 원문의 스포일러는 직접 제거하고 출처를 확인하세요. `shared_preferences`는 개인용 소규모 공략집 용도이며 대용량 DB나 클라우드 백업을 제공하지 않습니다. 앱 삭제 시 데이터가 사라집니다. 기기 성능에 따른 0.1초 조회 보장은 측정 전에는 주장하지 않습니다.

GitHub Actions 비밀값을 관리할 수 없는 환경에서 이미 서명한 APK를 게시하려면 `Publish verified signed APK` 워크플로우를 사용합니다. `deploy-artifacts/vX.Y.Z` 임시 브랜치 루트에 APK를 전달한 뒤 태그, main의 정확한 커밋 SHA, APK SHA-256을 지정해 수동 실행합니다. 워크플로우는 현재 앱 서명 인증서, 패키지·버전·아이콘·ARM64 구성과 체크섬을 검증하고 게시합니다. 완료 후 임시 브랜치를 삭제하세요. 서명 키를 교체하는 경우 워크플로우의 공개 인증서 지문도 검토·수정해야 합니다.

### 연결 실패 진단

AI Studio의 총 요청 수·성공률 그래프는 모델별 잔여 할당량 표시가 아닙니다. 앱도 HTTP 429만으로 사용량 소진을 단정하지 않습니다. 구체적인 QuotaFailure가 없으면 제한 항목 미확인으로 표시합니다. 오류에는 요청 종류, HTTP 코드, 허용된 Google 상태 코드, 선택 모델만 포함하며 원문 오류·API 키는 표시하지 않습니다. 알려진 제한 항목은 앱이 정한 요청 수·토큰·검색 도구 라벨로, 재시도 시간은 숫자로만 표시합니다.

설정에서 **일반 생성만 진단 (검색 제외)**를 누르면 검색 도구 없이 짧은 요청 1회를 보냅니다. 검색 포함 요청 결과와 따로 보관하고 **진단 결과 복사 (API 키 제외)**로 공유할 수 있습니다. 일반 생성 성공·검색 실패도 검색 한도 소진의 증거는 아니며, 일반 생성 성공만으로 검색 연결을 검증하거나 저장을 허용하지 않습니다. 진단은 사용자가 누를 때만 실행되고 자동 재시도는 없습니다. 키·모델 변경 시 결과를 지웁니다.
